## 3. The OAuth completion landing

- Its own headers (SCK:313-321): content-type, `referrer-policy: strict-origin` (SCK:315; `no-referrer` at base), `cache-control: no-store`, `x-frame-options: DENY`, and `default-src 'none'; script-src 'nonce-<nonce>'; form-action 'self'; base-uri 'none'; frame-ancestors 'none'` (SCK:318-320). The docblock states why (SCK:286-289). Only caller: CB:221-222, which passes the headers object as the Response init (`[source]`, RF 2.2).
- Why `no-referrer` was a latent breaker (RF:72, D1.0). The Fetch Standard, https://fetch.spec.whatwg.org/#append-a-request-origin-header (accessed 2026-10-29), for a request whose method is neither GET nor HEAD and whose mode is not "cors", under "no-referrer": "Set serializedOrigin to `null`."; under "strict-origin" only an https origin requesting a non-https URL gets `null` (verbatim quote at RF:72). The completion route refuses a POST that fails `sameOriginRequest`, and `Origin: null` fails it (RF:72, `[source]`). A browser obeying the landing's own `no-referrer` would have broken the Google sign-in; it never did only because of K0. `strict-origin` keeps a real Origin on the same-scheme POST and shrinks its Referer to the origin.
- It reaches no browser today (K0): the landing is served with NC's global CSP and `strict-origin-when-cross-origin` (NC:60, :62-65); X-Frame-Options is DENY either way. Under the global CSP the nonced auto-submit script runs (no `script-src` or `default-src`) and `form-action 'self'` admits the same-origin POST (`[source]`, RF 2.2). The landing was not served in any measured run (it needs Google and a real database; RF K4).
- The meta CSP and the meta referrer were NOT built (RF:71, D1's fallback). Two locked runs of `pnpm --filter @plexco/web exec playwright test e2e/oauth-completion-landing.spec.ts --list` (11:55:52 and 12:08:32 local time, 2026-10-29) listed 0 tests in 0 files. (1) At `261b59452d8c5198083ef959f2d6ae189d68c180`: `SyntaxError: Cannot use 'import.meta' outside a module` at `packages/db/src/index.ts:19`, reached through SCK's `@plexco/db` import from the spec. (2) Over a verbatim move of the builder into a new `apps/web/lib/completion-landing.ts` (never committed): the same SyntaxError from the spec's `import { SECURITY_HEADERS } from "../next.config.mjs"`, because NC:10 computes `repoRoot` from `import.meta.url` and Playwright 1.63's require hook turns the .mjs into CommonJS; the move also turned `apps/web/lib/tenant-lang.test.ts:341` red (the :339 test over DD-118's `SURFACE_BUCKETS`, :113-306), a file outside the lane's ownership. So the lane changed only the header value (SCK:315) and its docblock clause, and removed the spec. PRT:26-28 meets the same import blocker and copies the header values instead.
- What makes the browser check buildable (RF:71, last sentence): `SECURITY_HEADERS` in an `import.meta`-free module that NC imports and re-exports; the builder in a database-free module with its DD-118 `SURFACE_BUCKETS` entry in `apps/web/lib/tenant-lang.test.ts`; then the spec in the default testMatch, so CI's e2e job runs it.
