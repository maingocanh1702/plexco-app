## 3. Design (D1-D8)

- **D1 (conductor ruling RO-L40-1, RQ1 = R1).** The control is drawn ONLY for a seat row (`myStatus` `active` or `waitlisted`) whose club's tenant UUID came back from chat-context for this account (200 with a UUID-shaped tenantId through the parser of member-chat-gate.tsx:34-49). Every other row draws nothing: a 404, 429, 401, 5xx, network error, timeout or malformed body means no control for that club's rows, and no `?tenant=` is ever guessed or derived from the slug or any other source. USER-VISIBLE: guests see no control until the owner decides row `me-sessions-tenant-id-for-guest-leave`: R2a, a migration in a third Phase 4 slot (DD-150 allows only 0072 and 0073, docs/standards/decisions.md:1790) adding `tenant_id` to `account_my_sessions` and the /me/sessions DTO, reversing 0066:31 for guests; R2b, a new server-derived route `POST /api/me/sessions/[sessionId]/leave` plus a definer returning the tenant only for the caller's own live seat, so no tenant UUID reaches the browser and 0066:31 holds; recommended R2b. ## 4. Threat model

Defended, each with its pin (section 5 labels):

- **T1 a wrong or guessed tenant param.** Only a tenant UUID chat-context returned for this account's own club is used; anything else draws nothing (D1, D6). Pins: p1, p3, c1 (the `?tenant=` is exactly the UUID passed in), e1 (club B: no control and zero leave POSTs).
- **T2 a double submit or a replay creating two leaves.** One commandId per confirmed intent, kept across an uncertain failure; the in-flight ref (D8, JoinPanel's keeper). Pins: v3, e4 (the retry replays the SAME commandId), e5 (a double tap sends one POST).
- **T3 the UI drawing money or status the server did not send** (a leave that looks free but is not). No money, status or time computed in the UI; the server decides and the UI shows its 409 (D3, D4). Pins: v4, e3 (the pair, the row kept, no retry).
- **T4 leaking ids, tenant UUIDs or session ids into DOM text, URLs, logs or storage.** None rendered, logged or stored (D7). Pins: v7, e1 and e2 (the page URL unchanged, neither fixture id in the DOM text); the reviewers check the diff for console, localStorage and sessionStorage writes.
- **T5 a stale list after a leave.** The list reloads from the server through `onRetry` (D7). Pin: e2 (the list is fetched again and the row is gone).
- **T6 CSRF.** The session's csrfToken in the header, as JoinPanel (D8); the route's own check (CSRF_INVALID 403) is unchanged. Pin: c2.

Not defended (named): **N1** a guest who cannot resolve a tenant sees no control (D1; row `me-sessions-tenant-id-for-guest-leave`); **N2** the cancel of a pending request (Q10, D2; row `web-player-cancel-pending-request`).
