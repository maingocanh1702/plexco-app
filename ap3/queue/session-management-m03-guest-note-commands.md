## Problem
BE spec commands CreateGuestNote and DeleteGuestNote (docs/features/BE/feature_session_management_tech.md:702-725, algorithm) have zero implementation: session-service.ts exports exactly 6 functions today (createSession, publishSession, announceSession, updateSession, closeSession, cancelSession) and no guest-note code exists anywhere. The schema they consume IS live on main: migration packages/db/migrations/0044_session_guest_notes.sql (PR #12, merge 8eae449, 2026-09-11) added sessions.allow_player_invite, players.invited_by_person_id and the session_guest_notes table with RLS (tenant_isolation), grant SELECT/INSERT/DELETE only (no UPDATE), a same-tenant composite FK (tenant_id, session_id) -> sessions(tenant_id, id), and trigger trg_session_guest_note_limit which locks the sessions row FOR UPDATE before counting. Re-measure at your base: `ls packages/db/migrations | tail -1` must be 0044_session_guest_notes.sql and `grep -c session_guest_notes packages/db/schema.ts` must be >= 1; if either differs, HALT MISSING_CONTEXT.
## Acceptance
packages/db/src/session-service.ts gains createGuestNote and deleteGuestNote following the exact algorithm in BE spec section 4 'Guest Note management' (lines 702-725): session lock FOR UPDATE first (session-lock-ordering; the 0044 trigger takes the same row lock, so lock the session BEFORE inserting), status='open' + allow_player_invite=true guard (SESSION_NOT_OPEN / INVITE_NOT_ALLOWED), inviter-active guard (PLAYER_NOT_ACTIVE), 3-per-player limit pre-check before insert (GUEST_NOTE_LIMIT_REACHED -- the DB trigger is defense-in-depth, not a substitute), capacity check (active + guest-notes + live holds >= slots_max -> SESSION_FULL; there is no 'pending' status live, count it as 0), 1-100 char guest_name / 0-200 char note validation, commandId idempotency in the same processed_commands pattern as the other 6 commands, emit guest_note.created / guest_note.deleted outbox events. Routes: POST apps/web/app/api/sessions/[id]/guest-notes/route.ts (create) and DELETE apps/web/app/api/sessions/[id]/guest-notes/[noteId]/route.ts, both reusing the existing session-command-route choke-point (resolveSessionCommandContext / handleSessionCommand) exactly as the publish/close/cancel routes do -- both are body-carrying commands, so no change to apps/web/lib/session-command-route.ts is needed or allowed (it is outside scope). NO GET/list route in this slice: a body-less GET needs a resolver the choke-point does not have yet; that belongs to the supervised M2 slice (PLAN.md Milestone 2 / Deferred D5). Ownership check on delete: NOT_NOTE_CREATOR (403) if the caller did not create the note, GUEST_NOTE_NOT_FOUND (404) if it does not exist in the caller's tenant. Tests: BE unit rows #78 (happy path), #79 (4th note -> GUEST_NOTE_LIMIT_REACHED, service pre-check, not the trigger), #81 (delete, not creator -> NOT_NOTE_CREATOR) as real regression tests in session-service.test.ts (real Postgres, run by verify_host); route tests for POST and DELETE in the existing mocked-DB style (happy path, 403 non-admin/wrong tenant, 404). Error codes: register INVITE_NOT_ALLOWED, PLAYER_NOT_ACTIVE, SESSION_FULL, GUEST_NOTE_LIMIT_REACHED, NOT_NOTE_CREATOR, GUEST_NOTE_NOT_FOUND in API_ERROR_CODES (packages/core/src/api-contract.ts, keep the list sorted) with the statuses BE spec section 3 pins (lines 317-325), and extend the shipped-routes list in packages/core/src/api-contract.test.ts -- the same additive two-file edit the close/cancel routes made for CANCEL_REQUIRES_REVIEW. Do not collapse them onto FORBIDDEN/NOT_FOUND/INVALID_BODY and do not bypass err() with a raw Response. Actor identity: read personId from currentSession() in the route (as the choke-point itself does), no change to session-command-route.ts. 'Live holds' count as 0 (no holds table exists) with a comment, same treatment as the absent pending status.
