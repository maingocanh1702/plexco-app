# ap3 — a native Level-3 autopilot for Claude Code 2.1.x

> Generated by `ap3/install.sh` from ~/Projects/Claude template — never hand-edit; re-run install.sh to update.

A queued task starts a headless `claude -p` writer from launchd (no human command), which codes it
test-first inside the Claude Code sandbox and stops at a reviewable state. The **dispatcher** then
runs an independent Codex review and, only on a CLEAN verdict, opens a pull request with an evidence
row. The human's only job is to merge (or reject) the PR. Full design: `docs/level3-native/DESIGN.md`
(read `docs/level3-native/W1-DECISION-codex-sandbox.md` for the one place the build corrected it —
the review runs in the dispatcher, not the writer, because codex cannot initialize inside Seatbelt).

## Layout

```
ap3/
  dispatch.sh            the tick (launchd, every 15 min): reconcile + start one run, fail-closed
  install.sh <repo>      copy the kit into a target repo, write ap3/writer-settings.json + the plist (dry-run by default; --yes applies; --repo-wide re-enables the old .claude/settings.json merge)
  install-launchd.sh     write/load the dispatch (900s) + weekly report (Mon 09:00) plists
  review.sh              dispatcher's pinned Codex review (code|security) + the security-trigger heuristic
  scope-check.sh         git diff --name-only base..HEAD must be a subset of the task scope
  lint-task.sh           the §5.1 task-file gate — prints OK or INVALID_TASK <slug>: <reason>
  report.sh [--since 7d] cost / cycle-time / intervention monitor over the evidence rows
  aplib.py               shared brain: frontmatter parse, glob, scope classify, task lint, the PreToolUse hook
  rec.py evidence.py     run-record get/set ; one evidence JSONL row per run
  merge-settings.py      --repo-wide only: merge the writer settings into an existing .claude/settings.json (never clobbers)
  notify.sh              Telegram (no-op without ~/.ap-watch.env)
  hooks/scope-guard.sh   PreToolUse: deny an out-of-scope edit
  hooks/finish-guard.sh  Stop: don't stop until READY-FOR-REVIEW or HALT.md exists
  prompts/run.md         the headless writer prompt (points at the skill + task)
  routines.example.json  the registry shape (owner-edited only)
  queue/EXAMPLE.md       a task-file template (never dispatched — uppercase basename)
  settings.template.json the coding-only writer contract (+ .notes.md for the doc sources)
  skills/ap3-slice/       the writer procedure ; skills/ap3-review/ the verdict contract
  test/run.sh            the whole test suite -> AP3_KIT_TEST: PASS|FAIL
  probes/                the wave-1 de-risking probes (incl. probe-settings-flag.sh) + RESULTS.md
```

## Install into a target repo

```bash
bash /path/to/kit/ap3/install.sh /path/to/target        # DRY RUN: prints the plan + the writer-settings diff
bash /path/to/kit/ap3/install.sh /path/to/target --yes  # apply: copy machinery, write ap3/writer-settings.json, gitignore, plist
```

`install.sh` copies only the machinery — never your `routines.json`, `settings.<project>.json`,
queue tasks or docs. The writer's sandbox + permission contract is installed **per-run**: it is
written to a tracked `ap3/writer-settings.json` and the dispatcher hands it to the writer with
`claude --settings`. Install does **not** touch your `.claude/settings.json` by default — so the
sandbox and deny rules never govern your own interactive Claude Code sessions in that repo (the W1.1
finding: a repo-wide merge hard-denied `gh`/`git push`/`docker`/`psql` for every session). It adds
`ap3/env`, `ap3/state/`, `ap3/PAUSED` and `.ap3-run/` to `.gitignore`; the launchd plist is written
but **not loaded**.

> `--repo-wide` (opt-in, costly): ALSO merge the contract into the tracked, repo-wide
> `.claude/settings.json` (the old behaviour). That governs EVERY Claude Code session in the repo,
> including your own — use it only if you deliberately want the whole repo sandboxed.

## Queue a task

1. Copy `ap3/queue/EXAMPLE.md` to `ap3/queue/<slug>.md` and fill in Problem / Acceptance / Context.
   The scope globs are the ceiling; one concern, ~5 files or fewer.
2. `bash ap3/lint-task.sh ap3/queue/<slug>.md` until it prints `OK`.
3. Make sure the task's `class` exists and is `enabled` in `ap3/routines.json` (owner-edited only).
4. Commit `routines.json` + `ap3/writer-settings.json` (the per-run contract install wrote) + the
   queue file and **push `main`** — the dispatcher only reads `origin/main`, and it materializes the
   writer contract from there (a tick with no `ap3/writer-settings.json` on the base starts nothing).

The next tick starts it. You get a Telegram `✅ READY <slug> <PR url>` or `⛔ HALT <slug> <reason>`.
Merge the PR on GitHub. A merged-unchanged PR bumps the class's `clean_runs` in `ap3/state/trust.json`.

## Secrets for the writer — `ap3/env` (gitignored)

A launchd-started writer has no shell env. Put `KEY=VALUE` lines in `ap3/env` (gitignored); the
dispatcher sources it before starting the writer, so e.g. `DATABASE_URL_TEST=...` reaches a
sandboxed `pnpm test:db` without being tracked. Never commit `ap3/env`.

## Pause / stop

- Global kill switch: `touch ap3/PAUSED` — every tick exits `PAUSED`, no run starts.
- A class pauses automatically on any HALT / crash / rejected PR / human-fixed merge; re-enabling is
  a deliberate hand edit of `ap3/routines.json` (trust is re-earned, never auto-restored).

## Read the evidence

```bash
bash ap3/report.sh --since 7d        # runs, READY rate, mean/max cost, cycle time, interventions, denials, terminals
```

Rows come from `ap3/evidence.jsonl` (READY runs, on the PR branch) and `ap3/state/evidence.local.jsonl`
(HALTs). Unknown values are `null`/`unavailable`, never fabricated.

## Test the kit

```bash
bash ap3/test/run.sh                  # -> AP3_KIT_TEST: PASS
bash ap3/probes/probe-headless-permissions.sh   # the probes are re-runnable (real claude/codex; settings-flag probe ~$1.5)
```
